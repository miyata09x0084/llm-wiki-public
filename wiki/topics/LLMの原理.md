# LLMの原理

**LLM の原理は5段の因果で捉える: アーキテクチャ(並列化)→ 事前学習(次トークン予測)→ スケール(べき乗則)→ アライメント(RLHF)→ 推論(CoT)。各段が次段の前提条件になっている。** [[LLMの原理を学ぶ論文リスト(コア10本+拡張12本)]] を ingest するたびに、この総説へ統合する(進化する総説)。

応用・実務側の受け皿は [[LLM・AIエンジニアリング]]。本ページは原理側を担当する。

## 1. アーキテクチャ — 土台は Transformer、決定打は精度でなく並列性

出典: [[Attention Is All You Need (2017)]]。この段の結論は「並列化がスケーリングの土俵を作った」である。

- LLM の土台は [[Transformer]]。attention のみで系列を処理し、逐次計算を持たない
- 決定的だったのは翻訳精度(28.4 BLEU)そのものではなく**並列性**: 逐次演算 O(1) で学習が GPU に乗り、「大きくすれば賢くなるか」を試せる土俵ができた。したがって第3段(スケール)の前提条件
- 核心機構は [[Attention機構]] 1本: `softmax(QKᵀ/√dk)V`。現代 LLM はこの decoder 側(masked self-attention)だけを積んだ decoder-only 構成に収斂
- 積み残した弱点: 計算量 O(n²·d)(文脈長の2乗)。長文脈研究の出発点

## 2. 事前学習 — 次トークン予測は「あらゆるタスクの暗黙の重ね合わせ」だった

出典: [[BERT (2018)]] / [[GPT-3 (2020)]]。この段の結論は「予測だけで汎用能力が付き、適応は勾配更新からプロンプトへ移った」である。

- [[事前学習とfine-tuning]] の2段構えを BERT が確立(11タスク SOTA)。目的関数は MLM(文中の15%を隠して当てる、双方向・理解向き)と自己回帰 LM(次トークンを当てる、単方向・生成向き)の2流派で、生成 AI は後者に収斂
- GPT-3 の説明: Web テキストには翻訳・QA・算術などのタスクが暗黙に埋め込まれており、次トークン予測はその全てを一括学習する(外ループ)。推論時は [[in-context learning]] が文脈からタスクを認識・適応する(内ループ)
- 帰結: fine-tune 必須が崩れ「事前学習→プロンプト」へ転換。GPT-3 few-shot は fine-tuned SOTA に迫り、時に超えた(TriviaQA 71.2%)
- ⚠️ 残る未解明(GPT-3 自身が明記): few-shot は推論時にゼロから学ぶのか、学習済みタスクの認識にすぎないのか
