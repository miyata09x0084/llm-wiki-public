# AIネイティブ価値探索基盤

> **目的**: Wiki に限らず、生成AI全般の能力進化を「これまでにない次元の価値提供」の探索につなげる個人基盤。
> [[ベンダーロックインしない自作Wiki基盤の設計]] はこの基盤の一部(記憶層)として位置づけ直す。
> **性格**: 進化しつづける総説。実験の学びが溜まるたびに書き換える。

## 前提となる業界観

生成AIは「能力↑ × 推論コスト↓」の複利曲線を走っており、この曲線は**閾値を次々に越える**。閾値を越えた瞬間、それまで不可能・不経済だったものが製品クラスとして突然成立する。

例(ユーザー提示の2つ):

1. **個別即席アプリ** — 推論コストが十分落ちると、「仕様を言う → その人専用のアプリが瞬時に生成される」が経済的に成立。ソフトウェアが在庫(作り置き)から**その場のレンダリング結果(使い捨て)**に変わる。
2. **瞬時のマルチモーダル性** — 音声・映像・画像の理解/生成が会話速度・無視できる単価に達すると、「目の前の状況をそのまま入力にする」価値提供が成立。

この環境で勝敗を分けるのはモデルではない(モデルは全員が同じものを使える)。分けるのは:

- **閾値越えを早く検知できるか**(ウォッチ)
- **越えた瞬間に流し込める固有の文脈・データを持っているか**(蓄積)
- **数日で仮説を形にして検証できるか**(装置)

## 統一原理: 不変のコア + 再生成可能な派生物

この基盤全体を貫く原理は一つ。

> **耐久するのは「意図・仕様・データ」。それ以外(アプリ・UI・要約・派生物)はすべて、その時点の最良モデルによるレンダリング結果とみなし、いつでも捨てて再生成する。**

- Wiki の `raw/`(不変)→ `wiki/`(再生成可能)はこの原理の特殊例
- 「個別即席アプリ」はこの原理の極限形 — アプリすら派生物になる
- 帰結: **モデルが進化するたび、所有する全派生物が無料でアップグレードされる**。業界変化は脅威ではなく、保有資産の自動増価イベントになる

## 所有する3資産(基盤の実体)

| 資産 | 中身 | なぜ堀になるか |
|---|---|---|
| ① 文脈資産 | `raw/` + `wiki/`(自分・ドメイン・顧客についての蓄積) | モデルは共有物、文脈は固有物。能力がコモディティ化するほど差は文脈に移る |
| ② 仮説資産 | **閾値トリガー型の仮説バックログ**(下記) | 「何がいつ成立するか」を先回りして持つ者だけが、閾値越えの瞬間に動ける |
| ③ 実験装置 | 最小プロトタイプを数日で回すハーネス + 薄い能力継ぎ目 | 探索速度そのものが資産。試行回数 × 学習率が探索の複利 |

## 探索ループ

```
① 能力ウォッチ(新モデル・価格・レイテンシの変化を観測)
      ↓
② 仮説バックログ照合(どの閾値が越えられたか / 近づいたか)
      ↓
③ 最小実験(数日でプロトタイプ → 触って検証)
      ↓
④ 学びを wiki に還元(answers/ or 本ページ更新)→ ①へ
```

Wiki の ingest / query / lint は、このループの**記憶サブシステム**にあたる。

## アーキテクチャ(4層)

```
L3 学習層   : wiki/ — 実験の学び・仮説の帰結を蓄積(複利の場所)
L2 実験層   : lab/ — 使い捨てプロトタイプ群。各実験 = SPEC.md + 結果
L1 継ぎ目層 : 能力アダプタ — テキストに限らずマルチモーダル(視覚・音声・
              コード生成・エージェント実行)を薄く抽象化。config で差替
L0 資産層   : raw/ + 意図・仕様(不変のコア。すべてはここから再生成)
```

- L0/L3 は既にこのリポジトリに存在する(= 基盤はゼロからではない)
- L1 は薄く。L2 は捨てる前提で作る

## アンチパターン(この基盤における最大リスク)

1. **自作フレームワークによる自己ロックイン** — 最大のロックインはベンダーではなく、今日の能力の形に合わせて固めた自前の抽象化。モデルが scaffolding を飲み込むたびに負債化する(bitter lesson)。抽象は最小・使い捨て前提で。
2. **モデルの弱点補強への投資** — 今のモデルが苦手なことを補うコードは、次のモデルで無効化される。投資は「モデルが賢くなるほど価値が増す側」(データ・仕様・評価)に置く。
3. **プロトタイプの延命** — L2 は検証したら捨てる。延命した瞬間、保守負債となり探索速度が死ぬ。

## 仮説バックログ(閾値トリガー型)

形式: `成立条件(閾値) → 成立する価値提供`。ウォッチ対象の指標を添える。

| # | 閾値(成立条件) | 成立する価値 | ウォッチ指標 | 状態 |
|---|---|---|---|---|
| H1 | 「仕様→動くアプリ」が1回の対話・無視できる単価で成功率高く生成できる | 個別即席アプリ: 個人ごと・状況ごとの使い捨てソフトウェア | コード生成のトークン単価、ワンショット成功率 | **小規模では成立圏**(実験001) |
| H2 | リアルタイム音声・映像理解のレイテンシ<会話速度、単価<体験価値 | 瞬時マルチモーダル: 目の前の状況を即座に入力とする価値提供 | リアルタイムAPI の価格・レイテンシ | 監視中 |
| H3 | リアルタイム音声対話が「1日中つけっぱなし」で許容できる単価・レイテンシ | 常時同伴エージェント: 生活と仕事に常駐するコーチ/秘書。「使うAI」から「一緒にいるAI」へ | realtime audio API の単価/レイテンシ | 監視中 |
| H4 | 個人の全履歴(このWiki含む)を毎回フルロードしても無視できるコスト | 全文脈パーソナルAI: 「自分より自分を知る」助言。このWikiが直接の燃料 | 100万token級コンテキストの単価、キャッシュ価格 | 監視中 |
| H5 | 顧客一人のための専用ソフトが採算成立(H1の事業形態版) | N=1プロダクト: 「セグメント」概念の消滅、超ロングテール市場 | 生成成功率 × 保守の自動化度 | 監視中 |

- 照準の方針(2026-07-15): **意図的に絞らない**。仮説を広めに持ち、実験の手応えで絞る(CLAUDE.md「今のフォーカス」も同旨)

## 実験の学び(ループ④の蓄積)

### 実験001: 個別即席アプリ(H1) — 2026-07-15

「仕様→単一HTMLアプリ」を one-shot・修正禁止で生成し、実ブラウザで検証。**一発成功、コンソールエラーゼロ、全機能動作。** コスト実測: 6KB のアプリで Opus 4.8 ≈ ¥8.5/生成、Sonnet 5 ≈ ¥3.4、Fable 5 でも ≈ ¥17(thinking 未計上、実際は 1.5〜3×)。

**学び: H1 の残る障壁はコストではない。** 小規模・使い捨て・個人特化の領域ではすでに経済的に成立している。障壁は (a) 大規模アプリのワンショット成功率 (b) 仕様を引き出すUX (c) 保守・永続の扱い。「仕様の明確さ」が成功率の主変数という感触。詳細: `lab/001-instant-app/RESULT.md`
